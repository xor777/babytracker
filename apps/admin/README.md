# BabyTracker · админка `/dash`

Второй интерфейс проекта (`docs/CONTRACT.md` §10.4). Телевизионный дашборд только показывает —
этот нужен, чтобы **нажимать**: смотреть, что происходит, следить за динамикой, ловить ошибки
распознавания и править их руками. Основной экран — телефон, вёрстка от 390 px; десктоп вторичен.

**Главное ограничение дизайна: данных мало.** Ребёнку две недели, записей может не быть
сутками, а взвешивают раз в несколько дней. Поэтому каждый экран обязан быть осмысленным
при трёх событиях: пустое состояние здесь — норма, а не сбой, и оно объясняет, что будет
дальше и что для этого сказать Алисе. Пустой график с подписью «мало данных» — брак.

React 19 + Vite + TypeScript, без рантайм-зависимостей сверх React. Графики — рукописный SVG.

## Быстрый старт

Основной режим разработки — **против настоящего сервера**:

```bash
pnpm install                              # из корня репозитория

# терминал 1 — сервер на 8787
pnpm --filter @babytracker/server dev

# терминал 2 — админка на 5174, проксирует /api на 8787
pnpm --filter @babytracker/admin dev
```

Если сервер поднимать не хочется, рядом лежит `mock-server.mjs` — чистый node без
зависимостей, с семью днями истории, составными фразами и намеренными ошибками разбора:

```bash
pnpm --filter @babytracker/admin mock     # вместо терминала 1
```

Полезные режимы мока:

```bash
MOCK_EMPTY=1 node mock-server.mjs    # только вес при рождении — проверить пустые экраны
MOCK_401=1 node mock-server.mjs      # /api отвечает 401
MOCK_NO_UTTERANCES=1 node mock-server.mjs   # падает только /api/utterances
```

Формы ответов, потолки limit и коды ошибок в моке повторяют `apps/server` один в один —
специально, чтобы он не прятал расхождений. **Любую правку, меняющую работу с API,
проверяйте на настоящем сервере**, а мок приводите в соответствие следом.

Открыть: **http://localhost:5174/dash/** (именно с `/dash/` — у приложения `base: '/dash/'`).

### Сборка

```bash
pnpm --filter @babytracker/admin typecheck
pnpm --filter @babytracker/admin build     # → apps/admin/dist
```

`dist/index.html` ссылается на ассеты по `/dash/assets/...`. Если рядом с мок-сервером лежит
собранный `dist`, он отдаёт его по `http://localhost:8787/dash` — ровно так, как это будет
делать настоящий сервер.

### Полезные флаги мока

```bash
PORT=9000 node mock-server.mjs       # другой порт
MOCK_401=1 node mock-server.mjs      # /api отвечает 401 — проверить уход на экран сопряжения
API_PROXY_TARGET=http://host:8787 pnpm --filter @babytracker/admin dev
```

## Экраны

**Обзор** — открывается по умолчанию. Отвечает на вопрос «что с ним сейчас»: крупный
тикающий таймер текущего состояния, «когда в последний раз» ел / подгузник / спал,
полоса суток и итоги дня рядом с ориентирами. Сюда заходят девять раз из десяти,
поэтому он первый.

*Полоса суток* — сон блоками, кормления и подгузники засечками на оси времени. Свёрстана
дивами, а не SVG: позиции задаются процентами, а засечки остаются шириной в пиксель на любой
ширине экрана. Пустые сутки тоже осмысленны — ось часов на месте, отметка «сейчас» идёт.

**Сводка** — динамика. Период переключается, и **набор периодов зависит от возраста**:
двухнедельному «месяц» не предлагается, вместо него честное «с рождения». Формы выбраны
под смысл: для суток — крупные числа, ориентиры и промежутки между кормлениями;
для недели и дольше — столбцы по дням с полосой ориентира.

*График веса* сделан отдельно и подробно:

- ось X — **время, а не номер измерения**: взвешивают раз в несколько дней, и пробелы
  должны быть видны пробелами;
- **вес при рождении — базовая линия**, берётся как самое раннее измерение, без единого
  зашитого числа; заливка между кривой и линией показывает провал первых дней и возврат;
- в акценте — **прирост от рождения**, а не абсолютные граммы: именно его ждут родители;
- одно измерение — не повод рисовать «график» из одной точки: показывается число и
  объяснение, что следующее взвешивание покажет динамику;
- кривых ВОЗ у нас нет, **перцентили не считаются** — это была бы выдача догадки
  за медицинские данные.

**Журнал** — плоская лента, **новое сверху, без исключений**. Главная единица —
событие в разобранном виде, а не фраза Алисы: журнал открывают, чтобы увидеть,
что было, а не чтобы проверять качество разбора.

- Свёрнутая строка — время и суть в одну строку: «17:51 · Подгузник, мокрый»,
  «16:13 · Кормление, грудь, 28 мин, правая». На 390 px помещается 11 строк
  вместо трёх, которые давала прежняя раскладка вокруг фразы.
- По тапу строка разворачивается: исходная фраза Алисы, заметка модели,
  время начала и конца, уверенность, источник, «из той же фразы: …» для составных
  фраз, кнопки правки, удаления и отмены.

**Ошибки разбора не должны потеряться, спрятавшись под тап.** Поэтому свёрнутая
строка сама намекает, что её стоит развернуть: жёлтая полоска слева и знак «?».
Помечаются записи с низкой `confidence`, заметкой, начинающейся с `[?]` (так модель
отмечает собственное допущение), и фразы, разбор которых упал или завис. Пометка
спокойная: это данные о ребёнке, тревожный цвет здесь неуместен.

Ключевое: события стоят **гроздьями вокруг исходной фразы Алисы**. Видно, как «Андрей покушал
и уснул» превратилось в две записи (§10.3), и сразу заметно, если разбор наврал: рядом с записью
висит процент уверенности, если он низкий, и пометка «запись на другое время», если событие
уехало от фразы больше чем на 6 часов.

- у каждой записи есть видимая подпись **«✎ Править»**: строка и раньше нажималась целиком,
  но догадаться об этом было невозможно — отсюда и жалоба «не могу редактировать»;
- тап по строке открывает редактор: тип, подтип, начало, конец, значение с единицей, заметка;
- удаление мягкое, с тостом «вернуть» и отдельным фильтром «Удалённые» (§9.1 — физического
  удаления в системе не существует);
- фильтры по периоду (сутки / 3 дня / неделя / месяц) и по типу события.

**Период по умолчанию подбирается под данные.** Один запрос за самым свежим событием — и
выбирается ближайший пресет, который его покрывает. Иначе у двухнедельного ребёнка «Сегодня»
показывало бы пустой экран, на котором не за что даже нажать. Пустое состояние вдобавок
предлагает расширить период и показать удалённые.

### Что фраза сделала с дневником

Фраза может не создать ни одного события, а **изменить существующее**: «андрей проснулся»
закрывает начатый ранее сон. У такого события `utterance_id` указывает на другую, более
раннюю фразу, поэтому по нему связь не находится — и действие, поменявшее дневник,
выглядит не сделавшим ничего.

Связь «фраза → что она сделала» живёт в журнале ревизий: `GET /api/change-sets` отдаёт
`utterance_id` и `events: number[]`. Админка тянет его вместе с фразами и по нему
раскладывает карточки:

| что произошло | как показано |
|---|---|
| фраза создала записи | записи строками, «Отменить фразу» |
| фраза изменила чужую запись | «Изменила уже существующую запись» + сама запись (открывается), «Отменить изменение» |
| изменение уже откатили | «Изменила существующую запись — изменение отменено» |
| фраза ничего не изменила | не показывается (вопросы к Алисе, команды выхода) |
| разбор упал или никто не разобрал | янтарная карточка |

**Отмена** идёт через `POST /api/change-sets/:id/revert` — ту же ручку, что и возврат
удалённого. Сервер сам разбирает оба случая: созданные записи прячет (`deleted_at`,
физического удаления не существует — §9.1), изменённые возвращает в прежнее состояние.
Откат тоже журналируется, поэтому отменить отмену тоже можно.

**Набор может затрагивать несколько записей**, и откат вернёт их все. Сколько именно —
написано рядом с кнопкой, а при двух и более сначала спрашивается подтверждение.

### Какие фразы попадают в Журнал

Статус `skipped` на сервере означает три разные вещи, и валить их в одну кучу нельзя
(`src/lib/utterance.ts`):

| что это | пример | в Журнале |
|---|---|---|
| вопрос к Алисе (`query_state`) | «сколько он сегодня спал» | **нет** — это разговор с системой, а не событие жизни ребёнка |
| выход из диалога (`exit`) | «хватит» | **нет** |
| матчер справился сам, но данные изменил | «андрей проснулся» закрывает открытый сон | **да** — см. раздел выше: видно, что изменено, и есть отмена |
| матчер справился сам и данных не тронул | — | **нет** |
| матчер не понял и модель не приходила | `skipped` + `unknown` | **да**, янтарным: фразу никто не разобрал |
| разбор упал | `failed` | **да**, янтарным |
| висит в очереди дольше 10 минут | `pending` | **да**, янтарным |
| разбирается прямо сейчас | свежий `pending` | да, спокойным серым |

Счётчики считают ровно то, что нарисовано: записи и фразы отдельно. «0 записей» над пятью
карточками — это был прямой баг, а не мелочь.

**Сводка** — кормления, подгузники, сон и ростовые кривые за выбранный день из последних семи.
Факт рядом с возрастным ориентиром из `GET /api/stats/daily` (§10.1). Тон намеренно ровный:
никакого красного, никаких восклицаний, отклонение — констатация, а не диагноз; за неполные
сутки вердикт вообще не выносится. Медицинских советов нет нигде.

## Что нужно от сервера

| метод | путь | зачем |
|---|---|---|
| `GET` | `/api/events?from&to&type&limit&include_deleted` | лента (§3.3, §9.6) |
| `GET` | `/api/utterances?limit` | статусы разбора, **limit максимум 200** |
| `PATCH` | `/api/events/:id` | ручная правка (§10.4) |
| `DELETE` | `/api/events/:id` | мягкое удаление, отдаёт `revertWith` |
| `GET` | `/api/change-sets?limit` | найти, чем отменить чужое удаление (§9.6) |
| `POST` | `/api/change-sets/:id/revert` | вернуть удалённое (§9.6) |
| `GET` | `/api/stats/daily?days` | сводка и нормы (§10.4) |
| `GET` | `/api/state` | имя и возраст ребёнка в шапке (§3.2) |

**Исходный текст фразы** берётся из плоского поля `utterance_text`, которое сервер кладёт
в каждое событие (LEFT JOIN по `utterance_id`). Это основной источник: он приходит вместе
с лентой и не зависит от второго запроса. `/api/utterances` лишь добавляет статус разбора
и фразы, не давшие ни одной записи; если он не ответит, цитаты всё равно на месте, а в ленте
появится спокойная полоска о том, что статусы не загрузились. Молчать о такой поломке нельзя:
именно проглоченная ошибка когда-то убрала фразы с экрана целиком.

**Возврат удалённого** идёт только через журнал ревизий. Снять `deleted_at` патчем нельзя —
такого поля нет в схеме `PATCH`, и сервер отвечает 400; отдельной ручки `/restore` тоже
не существует. Ответ `DELETE` несёт `revertWith` — его и отправляем в
`POST /api/change-sets/:id/revert`. Если удаляли не в этой сессии, набор находится одним
запросом `GET /api/change-sets?limit=200`: там у каждого набора есть `events: number[]`.

Имена полей сводки — ровно серверные: `feeds{total,breast,bottle,solid,volumeMl}`,
`diapers{wet,dirty,both,total}`, `sleep{totalMin,sessions,longestMin}`,
`measures{weightG,heightCm,headCm,tempMaxC}`, `norms{feeds,wetDiapers,dirtyDiapers}`.
Дни приходят **по возрастанию**; клиент сортирует их сам, а «сегодня» определяет по дате,
а не по позиции в массиве. Ориентира по сну сервер не отдаёт — и мы его не выдумываем.

Из перечисленного обязателен только `GET /api/events`: без сводки, без статусов разбора
или без правки остальные экраны продолжают работать и показывают понятную ошибку
вместо пустоты.

## Приложение на домашнем экране (PWA)

`/dash` ставится как приложение, а не как закладка: `public/manifest.webmanifest`,
иконки, service worker.

- **Иконки** генерируются скриптом `node tools/make-icons.mjs` — чистый node,
  PNG кодируется вручную через zlib, зависимостей нет. Мотив взят у иконки навыка
  Алисы (`docs/assets/alice-icon-224.png`): один продукт должен узнаваться.
  Набор: 192 и 512 `any`, 192 и 512 `maskable` (рисунок ужат в безопасную зону —
  на Android углы обрежет), `apple-touch-icon` 180 и favicon 32.
- **Старт с иконки** — сразу «Обзор»: `start_url: /dash/#/overview`,
  `display: standalone`, `scope: /dash/`.
- **Офлайн**: service worker отдаёт последнее известное состояние и помечает ответ
  заголовком `x-cached-at`; приложение показывает полоску «Нет сети · данные от 19:45».
  Пустой экран или вчерашние цифры без пометки — недопустимы.
- **Сессия устройства** (§11): воркер ходит тем же `Request`, что создала страница, то есть
  с кукой; своего хранилища секретов ему не нужно. Ответы 401 не кэшируются никогда.
  Отдельно — ответы, полученные **через редирект**: без сессии сервер уводит переход на
  страницу сопряжения, `fetch` следует за ним молча и возвращает вполне успешный 200.
  Положив его в кэш под именем оболочки, воркер намертво подменил бы дневник экраном
  сопряжения. Поэтому `redirected === true` в кэш не попадает.

## Темы

Светлая, тёмная и «как в системе» (по умолчанию). Выбор хранится в `localStorage`
и переживает перезапуск; применяется inline-скриптом в `index.html` до первого кадра,
чтобы светлая тема не моргала тёмным. `theme-color` меняется вместе с темой — иначе
получилась бы тёмная строка состояния над светлым экраном.

Светлая тема — **не инверсия тёмной**: циан `#3fe9ff` на белом нечитаем, поэтому у неё
свои акценты, границы и настоящие тени вместо свечений. Правила CSS общие, тема меняет
только токены (`.theme-light` в `styles.css`).

Переключатель — в «Настройках» за шестерёнкой в шапке: темой пользуются один раз,
места на главном экране она не заслужила.

## Доступ

`/dash` и `/api/*` закрыты **сессией устройства** (§11): вход по коду сопряжения, никакого
пароля. Что делает приложение:

- **экран «Устройства»** (`components/DevicesScreen.tsx`): заявки с кодом и кнопками
  «Одобрить» / «Отклонить», список подключённых с отзывом, выход. Вкладки для него нет —
  заходят туда несколько раз в жизни; попасть можно из настроек и по баннеру, который
  появляется на главном экране сам, когда кто-то просится;
- **401 на `fetch`** уводит на `/pair`. Перезагрузка здесь не помогла бы и даже вредна:
  service worker честно отдаст сохранённую оболочку, и человек будет по кругу видеть
  работающее на вид приложение, которое не может получить ни одной цифры;
- **выход стирает офлайн-кэш** и снимает воркер с регистрации. Иначе человек, взявший
  потерянный телефон, открыл бы приложение и увидел настоящую историю ребёнка из памяти
  телефона, без всякого сервера.

Файл `sw.js` закрыт дверью, как и всё под `/dash`: скрипт воркера запрашивается в режиме
credentials `same-origin`, а регистрация идёт из уже загруженного приложения, у которого
сессия есть. Если браузер куку не пришлёт, отказ мягкий — приложение останется рабочим,
просто без офлайна, и напишет об этом в консоль.

## Заметки по устройству

- **`base: '/dash/'`** в `vite.config.ts` обязателен, иначе собранные ассеты уедут в корень.
- Маршрут живёт в хэше: `/dash/#/history`, `/dash/#/stats`. Так экран переживает перезагрузку
  и работает кнопка «назад», а серверу не нужен SPA-fallback на произвольные пути под `/dash`.
- Все времена в API — ISO 8601 UTC (§1); в локальную зону они переводятся только при показе,
  в БД уходит обратно UTC.
- **Секунды.** `datetime-local` знает только минуты, а у событий Алисы секунды есть. Поэтому
  «изменилось ли время» редактор решает в той же точности, в какой его видит человек: иначе
  сохранение «без правок» молча срезало бы секунды вместе с порядком событий внутри фразы
  (§10.3). Настоящее значение с секундами видно в карточке строкой «Записано».
- Пустое значение — это `NULL`, а не ноль (§10.2): редактор различает «не указано» и «ноль».
  Отрицательные значения и нечисловой ввод он не пропускает и говорит, что именно не так.
- Ошибки правки показываются **внутри карточки**: на телефоне она занимает почти весь экран,
  и баннер под ней человеку не виден.
