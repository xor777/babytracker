# BabyTracker · админка `/dash`

Второй интерфейс проекта (`docs/CONTRACT.md` §10.4). Телевизионный дашборд только показывает —
этот нужен, чтобы **нажимать**: смотреть историю, ловить ошибки распознавания и править их руками.
Основной экран — телефон, вёрстка от 390 px; десктоп вторичен.

React 19 + Vite + TypeScript, без рантайм-зависимостей сверх React. Графики — рукописный SVG.

## Быстрый старт

Основной режим разработки — **против настоящего сервера**:

```bash
pnpm install                              # из корня репозитория

# терминал 1 — сервер на 8787
pnpm --filter @babytracker/server dev

# терминал 2 — админка на 5174, проксирует /api на 8787
pnpm --filter @babytracker/admin dev
```

Если сервер поднимать не хочется, рядом лежит `mock-server.mjs` — чистый node без
зависимостей, с семью днями истории, составными фразами и намеренными ошибками разбора:

```bash
pnpm --filter @babytracker/admin mock     # вместо терминала 1
```

Формы ответов, потолки limit и коды ошибок в моке повторяют `apps/server` один в один —
специально, чтобы он не прятал расхождений. **Любую правку, меняющую работу с API,
проверяйте на настоящем сервере**, а мок приводите в соответствие следом.

Открыть: **http://localhost:5174/dash/** (именно с `/dash/` — у приложения `base: '/dash/'`).

### Сборка

```bash
pnpm --filter @babytracker/admin typecheck
pnpm --filter @babytracker/admin build     # → apps/admin/dist
```

`dist/index.html` ссылается на ассеты по `/dash/assets/...`. Если рядом с мок-сервером лежит
собранный `dist`, он отдаёт его по `http://localhost:8787/dash` — ровно так, как это будет
делать настоящий сервер.

### Полезные флаги мока

```bash
PORT=9000 node mock-server.mjs       # другой порт
MOCK_401=1 node mock-server.mjs      # /api отвечает 401 — проверить обработку Basic Auth
API_PROXY_TARGET=http://host:8787 pnpm --filter @babytracker/admin dev
```

## Экраны

**Журнал** — лента событий, свежие сверху, сгруппированные по дням.

Ключевое: события стоят **гроздьями вокруг исходной фразы Алисы**. Видно, как «Андрей покушал
и уснул» превратилось в две записи (§10.3), и сразу заметно, если разбор наврал: рядом с записью
висит процент уверенности, если он низкий, и пометка «запись на другое время», если событие
уехало от фразы больше чем на 6 часов.

- тап по строке открывает редактор: тип, подтип, начало, конец, значение с единицей, заметка;
- удаление мягкое, с тостом «вернуть» и отдельным фильтром «Удалённые» (§9.1 — физического
  удаления в системе не существует);
- фильтры по периоду (сутки / 3 дня / неделя / месяц) и по типу события.

Фразы, которые разбор не осилил (`failed`, `skipped`) или ещё не разобрал (`pending`), показаны
отдельной карточкой без записей — иначе упавший разбор исчезает бесследно. Успешно разобранные
фразы без новых событий не показываются: «проснулся» закрывает открытый сон и нового события
не создаёт, это нормальная работа, а не пробел.

**Сводка** — кормления, подгузники, сон и ростовые кривые за выбранный день из последних семи.
Факт рядом с возрастным ориентиром из `GET /api/stats/daily` (§10.1). Тон намеренно ровный:
никакого красного, никаких восклицаний, отклонение — констатация, а не диагноз; за неполные
сутки вердикт вообще не выносится. Медицинских советов нет нигде.

## Что нужно от сервера

| метод | путь | зачем |
|---|---|---|
| `GET` | `/api/events?from&to&type&limit&include_deleted` | лента (§3.3, §9.6) |
| `GET` | `/api/utterances?limit` | статусы разбора, **limit максимум 200** |
| `PATCH` | `/api/events/:id` | ручная правка (§10.4) |
| `DELETE` | `/api/events/:id` | мягкое удаление, отдаёт `revertWith` |
| `GET` | `/api/change-sets?limit` | найти, чем отменить чужое удаление (§9.6) |
| `POST` | `/api/change-sets/:id/revert` | вернуть удалённое (§9.6) |
| `GET` | `/api/stats/daily?days` | сводка и нормы (§10.4) |
| `GET` | `/api/state` | имя и возраст ребёнка в шапке (§3.2) |

**Исходный текст фразы** берётся из плоского поля `utterance_text`, которое сервер кладёт
в каждое событие (LEFT JOIN по `utterance_id`). Это основной источник: он приходит вместе
с лентой и не зависит от второго запроса. `/api/utterances` лишь добавляет статус разбора
и фразы, не давшие ни одной записи; если он не ответит, цитаты всё равно на месте, а в ленте
появится спокойная полоска о том, что статусы не загрузились. Молчать о такой поломке нельзя:
именно проглоченная ошибка когда-то убрала фразы с экрана целиком.

**Возврат удалённого** идёт только через журнал ревизий. Снять `deleted_at` патчем нельзя —
такого поля нет в схеме `PATCH`, и сервер отвечает 400; отдельной ручки `/restore` тоже
не существует. Ответ `DELETE` несёт `revertWith` — его и отправляем в
`POST /api/change-sets/:id/revert`. Если удаляли не в этой сессии, набор находится одним
запросом `GET /api/change-sets?limit=200`: там у каждого набора есть `events: number[]`.

Имена полей сводки — ровно серверные: `feeds{total,breast,bottle,solid,volumeMl}`,
`diapers{wet,dirty,both,total}`, `sleep{totalMin,sessions,longestMin}`,
`measures{weightG,heightCm,headCm,tempMaxC}`, `norms{feeds,wetDiapers,dirtyDiapers}`.
Дни приходят **по возрастанию**; клиент сортирует их сам, а «сегодня» определяет по дате,
а не по позиции в массиве. Ориентира по сну сервер не отдаёт — и мы его не выдумываем.

Из перечисленного обязателен только `GET /api/events`: без сводки, без статусов разбора
или без правки остальные экраны продолжают работать и показывают понятную ошибку
вместо пустоты.

## Доступ

`/dash` и `/api/*` закрыты HTTP Basic Auth на уровне Caddy (§10.4) — в коде для этого ничего
не делается, пароль спрашивает браузер. Но 401 на `fetch` обработан явно: вместо пустого экрана
показывается «Нужен вход» с кнопкой перезагрузки, после которой браузер снова спросит пароль.

## Заметки по устройству

- **`base: '/dash/'`** в `vite.config.ts` обязателен, иначе собранные ассеты уедут в корень.
- Маршрут живёт в хэше: `/dash/#/history`, `/dash/#/stats`. Так экран переживает перезагрузку
  и работает кнопка «назад», а серверу не нужен SPA-fallback на произвольные пути под `/dash`.
- Все времена в API — ISO 8601 UTC (§1); в локальную зону они переводятся только при показе,
  в БД уходит обратно UTC.
- **Секунды.** `datetime-local` знает только минуты, а у событий Алисы секунды есть. Поэтому
  «изменилось ли время» редактор решает в той же точности, в какой его видит человек: иначе
  сохранение «без правок» молча срезало бы секунды вместе с порядком событий внутри фразы
  (§10.3). Настоящее значение с секундами видно в карточке строкой «Записано».
- Пустое значение — это `NULL`, а не ноль (§10.2): редактор различает «не указано» и «ноль».
  Отрицательные значения и нечисловой ввод он не пропускает и говорит, что именно не так.
- Ошибки правки показываются **внутри карточки**: на телефоне она занимает почти весь экран,
  и баннер под ней человеку не виден.
