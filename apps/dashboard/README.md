# BabyTracker · Дашборд

Sci-fi HUD для телевизора: висит сутками на Android TV, 1920×1080, смотрят с трёх метров.
React 19 + Vite + TypeScript, графики — рукописный SVG, внешних зависимостей во время
исполнения нет (включая шрифты: только системные моноширинные стеки).

## Быстрый старт с мок-сервером

Настоящий сервер не нужен — рядом лежит `mock-server.mjs`, который реализует
`docs/CONTRACT.md` §3: REST, живой SSE-поток, засыпания/пробуждения и ленту фраз.

```bash
pnpm install                 # из корня репозитория

# терминал 1 — мок API на 8787
pnpm --filter @babytracker/dashboard mock

# терминал 2 — дашборд на 5173 (проксирует /api и /alice на 8787)
pnpm --filter @babytracker/dashboard dev
```

Открыть http://localhost:5173.

Мок каждые ~45 с переключает сон/бодрствование и подкидывает фразы в ленту.
Ускорить: `MOCK_TOGGLE_SEC=15 pnpm --filter @babytracker/dashboard mock`.

Проверить обрыв связи: погасить мок (Ctrl+C) — в строке состояния загорится
«нет связи · переподключаюсь», данные на экране останутся. Поднять обратно —
дашборд переподключится сам, без перезагрузки страницы.

Проверить работу без LLM (`claude` не установлен — по контракту §5 сервер обязан
жить и в этом режиме): `MOCK_NO_CLAUDE=1 pnpm --filter @babytracker/dashboard mock`.
Фразы уйдут в статус `skipped`, в строке состояния вместо очереди появится
«разбор фраз недоступен». Это штатный режим, поэтому он показан нейтрально, не красным.

## С настоящим сервером

Сервер по контракту слушает 8787 — конфигурация dev-прокси совпадает, ничего менять
не нужно. Если сервер на другой машине:

```bash
API_PROXY_TARGET=http://192.168.1.10:8787 pnpm --filter @babytracker/dashboard dev
```

## Сборка и выкладка

```bash
pnpm --filter @babytracker/dashboard build      # tsc --noEmit + vite build → dist/
pnpm --filter @babytracker/dashboard typecheck
```

`dist/` — статика, которую отдаёт сервер BabyTracker. Телевизор открывает её с адреса
сервера, поэтому по умолчанию API берётся с того же origin и настраивать нечего.

Если фронт живёт отдельно от API — задать базовый URL на этапе сборки:

```bash
VITE_API_BASE=http://tracker.local:8787 pnpm --filter @babytracker/dashboard build
```

Посмотреть собранное вместе с моком (мок сам отдаёт `./dist`, если он есть):

```bash
pnpm --filter @babytracker/dashboard build
pnpm --filter @babytracker/dashboard mock
# → http://localhost:8787
```

## Как это устроено

| Файл | Зачем |
|---|---|
| `src/api.ts` | REST-обёртки, `VITE_API_BASE`, терпимый разбор ответов |
| `src/hooks/useTracker.ts` | SSE + REST, переподключение, активная проверка связи |
| `src/hooks/useClock.ts` | секундный тик и масштабирование сцены |
| `src/components/*` | блоки экрана |
| `src/styles.css` | вся вёрстка и оформление HUD |
| `mock-server.mjs` | мок сервера по контракту §3 |

### Решения, которые стоит знать

- **Сцена 1920×1080 масштабируется целиком.** Вся вёрстка в абсолютных пикселях, а
  `--stage-scale` (JS + `ResizeObserver`) ужимает её под реальный экран. На 1280×720
  и в любом окне браузера картина та же, просто меньше; скролла нет никогда.
- **Таймер тикает локально** раз в секунду и выровнен по часам сервера
  (`state.now` → сдвиг), сервер для этого не дёргается.
- **Связь.** `EventSource` переподключается сам; сверх этого раз в 15 с проверяем
  тишину в потоке и, если её больше 25 с, сами ходим за `/api/state`. Это ловит
  случай, когда прокси (vite, nginx, Cloudflare Tunnel) держит сокет открытым, хотя
  бэкенд уже умер — тогда `EventSource` молчит и ошибки не даёт. Если поток молчит
  дольше двух минут при живом HTTP, он пересоздаётся.
- **Данные при обрыве не пропадают:** неудачные запросы ничего не затирают.
- **Выгорание OLED:** фон — настоящий чёрный, вся вёрстка очень медленно дрейфует
  (цикл ≈7 минут, ±8 px), яркие статичные элементы не стоят пиксель в пиксель.
- **Ничего интерактивного:** курсор скрыт, кликать нечего, скролла нет.

### Контракт

Форматы данных — `docs/CONTRACT.md` §3. Менять их в одностороннем порядке нельзя:
на тот же документ опирается сервер.

Уточнения, согласованные с backend поверх контракта:

- `fast_result` и `llm_result` приходят **объектами**, а не JSON-строками
  (в БД это TEXT, наружу сервер отдаёт разобранное значение). Строку дашборд тоже
  переживёт — на случай сырого поля.
- Статус `skipped` — нормальный, а не ошибка: LLM-разбора не было.
- `/healthz` отдаёт сверх контракта `worker.claudeAvailable` / `worker.claudeProblem`;
  дашборд опрашивает его раз в минуту только ради индикатора.
- `/api/events` может вернуть `type: 'note'` — на ленту сна такие события не попадают.
- Обёртка ответа `/api/utterances` в контракте не зафиксирована: принимается и
  `{utterances: []}`, и голый массив.
