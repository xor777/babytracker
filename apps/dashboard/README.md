# BabyTracker · Дашборд (ANDREYTRACKER)

Sci-fi HUD для телевизора: висит сутками на Android TV, 1920×1080, смотрят с трёх метров.
React 19 + Vite + TypeScript, графики — рукописный SVG, внешних зависимостей во время
исполнения нет (включая шрифты: только системные моноширинные стеки).

`ANDREYTRACKER` — только надпись на экране; пакеты, каталоги и id приложения остаются
`babytracker`.

## Что на экране

| Блок | Что отвечает |
|---|---|
| Главная строка (слева) | самое конкретное из верного: `СПИТ` / `КУШАЕТ` / `БОДРСТВУЕТ` + тикающий таймер |
| Питание (справа) | последнее кормление: чем, сколько, как давно, какое по счёту |
| Последние 24 часа | ритм суток: полоса сна и отметки кормлений на одной оси |
| Вес | текущий вес, прирост от веса при рождении, график от базовой линии |
| Сутки | сон, кормления, подгузники — числа за текущие сутки с подстрочником |
| Эфир | последние фразы и что они записали |
| Строка состояния | связь, очередь разбора, возраст, время |

### Чего на экране нет и почему

- **14-дневных столбцов сна.** Слот занял вес: его просил заказчик, а сон и так
  представлен трижды (главная строка, лента суток, счётчик за сутки). У ребёнка первых
  недель двухнедельная история сна почти пустая и уступает по пользе весу.
- **Дорожки подгузников на ленте суток.** Третья дорожка превращала ленту в шум;
  подгузники остались счётчиком с разбивкой мокрые/грязные.
- **Роста, окружности головы, лекарств, симптомов, сцеживания, активностей.** Данных
  по ним пока нет вовсе, а место конечно. Идущее занятие (купание, прогулка, сцеживание)
  при этом уже поддержано главной строкой — появится в данных, появится и на экране.
- **Точных чисел у каждого взвешивания.** Подписаны крайние даты и последнее значение,
  остальное читается по базовой линии: подписи налезали друг на друга.

## Быстрый старт с мок-сервером

Настоящий сервер не нужен — рядом лежит `mock-server.mjs`, который реализует
`docs/CONTRACT.md` §3: REST, живой SSE-поток, засыпания/пробуждения и ленту фраз.

```bash
pnpm install                 # из корня репозитория

# терминал 1 — мок API на 8787
pnpm --filter @babytracker/dashboard mock

# терминал 2 — дашборд на 5173 (проксирует /api и /alice на 8787)
pnpm --filter @babytracker/dashboard dev
```

Открыть http://localhost:5173.

Мок каждые ~45 с переключает сон/бодрствование и подкидывает фразы в ленту.
Ускорить: `MOCK_TOGGLE_SEC=15 pnpm --filter @babytracker/dashboard mock`.

Проверить обрыв связи: погасить мок (Ctrl+C) — в строке состояния загорится
«нет связи · переподключаюсь», данные на экране останутся. Поднять обратно —
дашборд переподключится сам, без перезагрузки страницы.

Проверить незакрытое кормление:
`MOCK_OPEN_FEED=fresh` — идёт прямо сейчас (главная строка «КУШАЕТ»),
`MOCK_OPEN_FEED=stale` — фразу «поел» забыли, порог пройден («НЕ ЗАКРЫТО»).

Проверить работу без LLM (`claude` не установлен — по контракту §5 сервер обязан
жить и в этом режиме): `MOCK_NO_CLAUDE=1 pnpm --filter @babytracker/dashboard mock`.
Фразы уйдут в статус `skipped`, в строке состояния вместо очереди появится
«разбор фраз недоступен». Это штатный режим, поэтому он показан нейтрально, не красным.

## С настоящим сервером

Сервер по контракту слушает 8787 — конфигурация dev-прокси совпадает, ничего менять
не нужно. Если сервер на другой машине:

```bash
API_PROXY_TARGET=http://192.168.1.10:8787 pnpm --filter @babytracker/dashboard dev
```

## Сборка и выкладка

```bash
pnpm --filter @babytracker/dashboard build      # tsc --noEmit + vite build → dist/
pnpm --filter @babytracker/dashboard typecheck
```

`dist/` — статика, которую отдаёт сервер BabyTracker. Телевизор открывает её с адреса
сервера, поэтому по умолчанию API берётся с того же origin и настраивать нечего.

Если фронт живёт отдельно от API — задать базовый URL на этапе сборки:

```bash
VITE_API_BASE=http://tracker.local:8787 pnpm --filter @babytracker/dashboard build
```

Посмотреть собранное вместе с моком (мок сам отдаёт `./dist`, если он есть):

```bash
pnpm --filter @babytracker/dashboard build
pnpm --filter @babytracker/dashboard mock
# → http://localhost:8787
```

## Как это устроено

| Файл | Зачем |
|---|---|
| `src/api.ts` | REST-обёртки, `VITE_API_BASE`, терпимый разбор ответов |
| `src/hooks/useTracker.ts` | SSE + REST, переподключение, активная проверка связи |
| `src/hooks/useClock.ts` | секундный тик и масштабирование сцены |
| `src/components/*` | блоки экрана |

### Параметры запуска на телевизоре

К адресу можно добавить query-параметры — перезбирать ничего не нужно:

| Параметр | Зачем |
|---|---|
| `?debug=1` | Панель метрик поверх экрана: видимая область, масштаб, `clientWidth`, `innerWidth`, `visualViewport`, dpr, состояние связи. С неё снимается диагноз, если картинка не влезла. |
| `?safe=0.92` | Запас на overscan (по умолчанию `0.95`). Меньше — сильнее ужимается, больше свободного поля по краям. `?safe=1` — впритык, без запаса. |

На сборке запас задаётся через `VITE_SAFE_AREA=0.92`.

### Сон — состояние, кормление — занятие

Они лежат слоями, а не конкурируют: «спит или нет» верно всегда, «кушает» происходит
внутри бодрствования. Главная строка показывает **самое конкретное из верного**.

Открытое кормление умеет врать: чтобы засечь длительность, нужны две фразы, и вторую
забывают — особенно ночью. Поэтому у открытых событий есть порог, после которого они
перестают считаться идущими (`OPEN_LIMIT_MIN` в `src/lib/day.ts`):

| событие | порог |
|---|---|
| кормление | 90 мин |
| сцеживание | 45 мин |
| купание | 60 мин |
| прогулка | 180 мин |
| время на животе | 45 мин |

После порога главная строка возвращается к `БОДРСТВУЕТ`, а кормление показывается
нейтрально: «не закрыто, начато в 19:06, окончание неизвестно». **Сами мы его не
закрываем** — когда оно кончилось, никто не сказал, а выдумывать факты нельзя.
У сна порога нет: шесть часов сна — это правда, а не забытая фраза.

### Решения, которые стоит знать

- **Сцена 1920×1080 масштабируется целиком.** Вся вёрстка в абсолютных пикселях, а
  JS (`useStage`) считает масштаб и сдвиг. На 1280×720 и в любом окне браузера картина
  та же, просто меньше; скролла нет никогда.
- **Размер видимой области берётся как минимум из трёх источников** —
  `documentElement.clientWidth`, `window.innerWidth` и `visualViewport`. Они расходятся:
  WebView телевизора умеет держать лейаут-вьюпорт 1920, когда реально видно 1280, и тогда
  `clientWidth` врёт, а правая треть экрана (включая часы) уезжает за кадр. Позиционируем
  от левого верхнего угла собственным сдвигом, а не `left: 50%`, по той же причине.
- **Запас на overscan** — по умолчанию 5%: телевизоры часто подрезают края физически.
- **Таймер тикает локально** раз в секунду и выровнен по часам сервера
  (`state.now` → сдвиг), сервер для этого не дёргается.
- **Связь.** `EventSource` переподключается сам; сверх этого раз в 15 с проверяем
  тишину в потоке и, если её больше 25 с, сами ходим за `/api/state`. Это ловит
  случай, когда прокси (vite, nginx, Cloudflare Tunnel) держит сокет открытым, хотя
  бэкенд уже умер — тогда `EventSource` молчит и ошибки не даёт. Если поток молчит
  дольше двух минут при живом HTTP, он пересоздаётся.
- **Данные при обрыве не пропадают:** неудачные запросы ничего не затирают.
- **Выгорание OLED:** фон — настоящий чёрный, вся вёрстка очень медленно дрейфует
  (цикл ≈7 минут, ±8 px), яркие статичные элементы не стоят пиксель в пиксель.
- **Ничего интерактивного:** курсор скрыт, кликать нечего, скролла нет.

### Контракт

Форматы данных — `docs/CONTRACT.md` §3. Менять их в одностороннем порядке нельзя:
на тот же документ опирается сервер.

Уточнения, согласованные с backend поверх контракта:

- `fast_result` и `llm_result` приходят **объектами**, а не JSON-строками
  (в БД это TEXT, наружу сервер отдаёт разобранное значение). Строку дашборд тоже
  переживёт — на случай сырого поля.
- **На экран не попадает ни одно служебное имя поля.** `llm_result` — это конверт
  claude CLI (`{"type":"result","session_id":…,"usage":…}`), а не разбор фразы; наивное
  чтение `type` печатало на телевизоре слово «result». Поэтому `llm_result` не
  рендерится вообще, из `fast_result` берётся только известный `kind` по белому списку,
  а что фраза на самом деле записала, берётся из событий по `utterance_id`.
- Статус `skipped` — это **успех**: fast-path разобрал фразу уверенно, и звать модель
  не понадобилось (`llm_error` при этом вида «не отправлено модели: fast-path уверенно
  разобрал как sleep_start (0.95 >= 0.8)»). В ленте он выглядит как «записано».
  Красного в ленте нет вовсе — экран висит в детской, и тревожный цвет там ни к чему.
- `/healthz` отдаёт сверх контракта `worker.claudeAvailable` / `worker.claudeProblem`;
  дашборд опрашивает его раз в минуту только ради индикатора.
- `/api/events` может вернуть `type: 'note'` — на ленту сна такие события не попадают.
- Обёртка ответа `/api/utterances` в контракте не зафиксирована: принимается и
  `{utterances: []}`, и голый массив.
