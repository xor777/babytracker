# Подключение навыка Алисы

Пошагово: от пустой консоли до фразы «Алиса, запусти дневник Андрея» на станции.

Названия полей в консоли Яндекса иногда меняются — ориентируйся по смыслу, если
что-то называется чуть иначе.

## Шаг 0. Получить публичный URL

Алиса ходит только по HTTPS с валидным сертификатом. codex-vm сидит за NAT без публичного
IP, поэтому наружу её выводит Cloudflare Tunnel.

```bash
ssh codex-vm 'bash ~/babytracker/infra/tunnel-url.sh'
```

Скрипт напечатает `Webhook URL` — строку вида
`https://что-то-случайное.trycloudflare.com/alice/<32 hex-символа>`.
Секрет в пути — это и есть аутентификация вебхука, **никому его не показывай**
и не выкладывай в публичный репозиторий.

> **Важно про быстрый туннель.** Бесплатный `trycloudflare.com` выдаёт новый случайный адрес
> при каждом перезапуске. Для первых проверок это нормально, но после перезапуска VM URL
> придётся менять в консоли Диалогов. Как перейти на постоянный домен — в [DEPLOY.md](DEPLOY.md).

## Шаг 1. Создать навык

1. Открой [dialogs.yandex.ru/developer](https://dialogs.yandex.ru/developer) под своим Яндекс-аккаунтом —
   тем же, к которому привязана станция, иначе навык на ней не запустится.
2. **Создать диалог** → тип **Навык в Алисе**.

## Шаг 2. Заполнить настройки

| Поле | Значение |
|------|----------|
| Название | `Дневник Андрея` |
| Активационное имя | `дневник Андрея` |
| Backend | `Webhook URL` → адрес из шага 0 |
| Хочу получать события | не нужно |
| Использовать модель Алисы | **выключить** — фразы разбираем сами |

Требования Яндекса к активационному имени ([документация](https://yandex.ru/dev/dialogs/alice/doc/ru/requirements)):

- от двух до четырёх слов;
- нельзя слова «Яндекс», «Алиса», «Станция» и служебные вроде «запусти», «покажи»;
- не должно совпадать с уже существующим навыком **вплоть до созвучия** — если модерация
  завернёт из-за похожести, бери вариант подлиннее: `дневник малыша Андрея`;
- избегай выдуманных слов: незнакомому слову Алиса учится 2–3 недели после публикации,
  а обычные русские слова распознаёт сразу.

## Шаг 3. Проверить без публикации

Самый быстрый способ убедиться, что связка работает — **вкладка «Тестирование»** в консоли.
Публиковать для этого ничего не нужно.

Прогони по порядку и сверься с ожидаемым:

| Фраза | Что должна ответить Алиса |
|-------|---------------------------|
| *(открытие навыка)* | приветствие, сессия остаётся открытой |
| `Андрей заснул` | `Записала: Андрей заснул в HH:MM` |
| `Андрей заснул` (повторно) | `Андрей уже спит, с HH:MM…` — дубликат не создаётся |
| `Андрей проснулся` | `Андрей проснулся. Спал N минут` |
| `сколько он сегодня спал` | сводка за сутки |
| `его сегодня вырвало после смеси` | `Приняла: «…». Сейчас разберу` — дальше разберёт Claude |
| `хватит` | прощание, сессия закрывается |

Параллельно смотри, что происходит на сервере:

```bash
ssh codex-vm 'journalctl --user -u babytracker -f'
```

В логе при первом запросе будет видно `alice_user_id` — **скопируй его** и пропиши на сервере,
чтобы вебхук перестал принимать кого попало:

```bash
ssh codex-vm
nano ~/babytracker/.env          # ALICE_ALLOWED_USER_IDS=<id сюда>
                                 # ALICE_SKILL_ID=<id навыка из консоли>
systemctl --user restart babytracker
```

## Шаг 4. Опубликовать приватно

Чтобы навык заработал на настоящей станции, его придётся опубликовать — но **приватно**:
такой навык [не попадает в каталог](https://webmaster.yandex.ru/blog/v-yandeks-dialogakh-poyavilas-vozmozhnost-sozdavat-privatnye-navyki)
и запускается только теми, кто знает активационную фразу.

1. Вкладка **Публикация** → включить признак приватности (навык доступен только по ссылке /
   по активационной фразе, в каталоге не показывается).
2. Заполнить обязательное для модерации: описание, иконка, пример фраз.
3. Отправить на модерацию. Приватные навыки проходят её заметно проще публичных, но
   **какое-то время это займёт** — обычно от нескольких часов до пары суток.

После публикации:

> — Алиса, запусти дневник Андрея
> — Слушаю
> — Андрей заснул
> — Записала: Андрей заснул в 21:14

Сессия остаётся открытой, так что события можно надиктовывать подряд, не повторяя
активационную фразу каждый раз.

## Если что-то не работает

| Симптом | Куда смотреть |
|---------|---------------|
| «Навык не отвечает» | Ответ дольше 3 секунд. `journalctl --user -u babytracker -f` — ищи, что тормозит в горячем пути |
| Ошибка в консоли на Webhook URL | Туннель упал: `systemctl --user status babytracker-tunnel`, URL мог смениться |
| Отвечает, но события не появляются | Смотри `/api/utterances` — фраза записалась? Дальше `status` разбора |
| Разбор вечно `pending` | Worker или claude CLI. `ssh codex-vm 'claude -p "тест"'` — проверь авторизацию |
| На станции «не знаю такого навыка» | Не опубликован приватно, либо станция на другом Яндекс-аккаунте |
